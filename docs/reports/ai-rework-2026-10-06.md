# The AI layer, reworked: the engine concludes, the analytics reduce, the model asks and explains

**Date:** 2026-10-06. **Status:** built the same day on `feat/guardrails-agents-import` (engine `analysis.py` and `sensitivity.py`, the API's `digest_run` and `run_notes`, the planner's run state machine, Limits tab and note; the roster, the reviewer, the health thread and the filing tools deleted). Measured live on main: the digest is 3.2 kB and a note costs $0.013–0.014; 513 N-1 rows fold into 36 causes; the DC factors take 0.13 s for 114 buses and injecting the predicted room takes the worst AC loading to 92–98 %. The owner's brief: "rethink how we make this an AI-first platform; it analyses big data;
rework the AI part exactly as proposed; clean, KISS, DRY, SOLID; remove everything we no longer use; the processing
UX (runs that show in the background, pop-ups that do or do not appear, double triggers, disabled buttons, errors) and
the findings UX (800–1000 rows on a small screen) are part of it."

## What was wrong

The language model sat where the big data is. A reviewer read 750 gate rows to restate them; specialists read
hundreds of study items to file a handful of findings and, with the weaker model, filed none; a steward triaged events
by reading the ledger. Every improvement that earned trust this week was deterministic (collapse classification,
grouping per outage and case, the binding case on every figure). A model is the slowest, dearest and least reliable
reader of a table we own, and the planner showed the same table to a person.

## The shape

Three layers, each with one job:

1. **Engine** (`packages/optimizer`): solves. Unchanged physics.
2. **Analytics** (`gridforge_optimizer/analysis.py`, `sensitivity.py`): reduces a run's outputs into engineer-shaped
   objects, deterministically, with no model: the **binding set** (which elements bind, from which year, in which case,
   by how many MW, loaded by which projects, breached by which outages), **causal chains** for every deferral (project →
   element → case → year → what MW would connect), **consequence clusters** of the N-1 and ledger rows (twelve outages
   that strand the same 1.1 MW are one cause), and a **digest** of all of it under about 2 kB. Sensitivity factors
   (DC PTDF/LODF on the solved case) pre-rank "where can X MW connect" so the AC solve confirms only the top few.
3. **Language** (`apps/api/.../agents`): two roles only. The **note**: one model call per run that turns the digest
   into a 150-word engineer's note, every figure bound by value to the digest. The **answerer**: an operator's question
   in a thread, planned as typed queries over the analytics and the studies, cited step by step, with proposals the
   operator approves. No roster, no sweeps, no model-written findings.

## What goes

The steward and its triage, the seven specialists, the reviewer and the `reviews` table, `steward_brief`, the `filing`
tools, the health thread, the runs popover's roles, token streaming for runs nobody watches, every place a model copies
a figure out of a table.

## The planner

- **Runs** have one state machine (idle → queued → running(stage) → finishing → done | failed | superseded), one owner
  (`useRun`), one surface (the docked run card) whether the run was started by a button, an edit, a switch or an
  approval; buttons that would start, merge or edit mid-run are disabled with the reason in their title; a superseded
  job is cancelled, never shown; one toast channel for errors, each with its retry.
- **Limits** replaces the findings list: the binding set ranked, each element with its trajectory, first binding year,
  headroom, the projects it holds back and the outages that breach it; the clusters; the deferrals with their chains;
  rows only on demand, filtered to the element in hand.
- **Review** shows the diff, the gate and the engineer's note for the run. The note also sits under the result stamp
  on main.
- **Ask** stays: one conversation, typed queries, cited answers, proposals to approve.

## Cost

One model call per run (about $0.05) and one per question, against six to twelve calls and $0.5–1 per run before.
